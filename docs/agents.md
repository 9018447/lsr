# Agent体系使用指南

## 设计理念
本工具的Agent体系严格遵循「开发者主导、AI辅助」的结对编程定位：
1. 所有Agent输出均为建议，不直接修改代码，需开发者确认后才会执行
2. Agent不会主动生成超出用户需求的功能，所有输出严格对齐用户意图
3. Agent输出的所有变更都会附带影响范围评估和风险说明
4. 所有Agent的能力边界明确，不会给出超出自身能力范围的建议

## 内置Agent介绍

### 1. 代码评审Agent (`/agent review`)
#### 调用方式
```
/agent review <文件路径> [--rule <评审规则>]
```
#### 能力范围
- 代码规范检查：符合PEP8/ESLint等对应语言的规范
- 性能问题识别：低效算法、资源泄漏、重复查询等问题
- 安全风险扫描：注入风险、权限漏洞、敏感信息泄露等
- 可维护性评估：重复代码、逻辑复杂度、命名规范等问题
#### 输出规范
- 问题分级：高/中/低三个风险等级
- 每个问题附带：位置、问题描述、修复建议、影响范围
- 修复建议可直接点击应用到代码

### 2. 重构辅助Agent (`/agent refactor`)
#### 调用方式
```
/agent refactor <重构目标> [--scope <影响范围>]
```
#### 能力范围
- 函数/类的提取、拆分、合并
- 重复代码抽象
- 依赖解耦方案
- 接口升级兼容方案
#### 输出规范
- 重构步骤说明，每一步都是可独立执行的原子操作
- 重构前后的代码对比
- 依赖影响列表，明确哪些调用方需要同步修改
- 风险评估：明确重构是否会破坏现有功能

### 3. 调试排障Agent (`/agent debug`)
#### 调用方式
```
/agent debug <错误信息> [--file <相关文件>]
```
#### 能力范围
- 报错根因定位，结合代码调用链路分析
- 最小复现用例生成
- 修复方案输出，附带验证方法
- 同类问题预防建议
#### 输出规范
- 根因分析：明确错误的触发链路和根本原因
- 修复方案：提供1-3种可选修复方式，说明各自优劣
- 验证步骤：如何验证修复是否有效
- 预防措施：如何避免同类问题再次发生

### 4. 架构设计Agent (`/agent arch`)
#### 调用方式
```
/agent arch <设计需求> [--existing <现有架构说明>]
```
#### 能力范围
- 新功能模块架构设计
- 现有架构演进方案
- 技术选型评估
- 领域模型设计
#### 输出规范
- 架构图说明（Mermaid格式）
- 模块职责划分
- 接口定义规范
- 技术选型理由和风险评估
- 演进路线建议

## 自定义Agent开发
你可以通过以下方式扩展自定义Agent：
1. 在`aider/agents/`目录下新建Agent类，继承`BaseAgent`
2. 实现`invoke()`方法，接收用户输入，返回Agent输出
3. 在`aider/agents/registry.py`中注册新的Agent
4. 新增对应prompt模板到`aider/prompts/agents/`目录下

示例模板可参考内置Agent的实现代码。
